¿Qué es una API? Cómo viaja un pedido en la web

Cliente, servidor y base de datos: entendé qué pasa desde que hacés clic hasta que aparece la información en pantalla.

7 de octubre de 2026 ·6 min de lectura

Categoría: Back-end

Cada vez que abrís una aplicación para ver el clima, pedir comida o revisar tus mensajes, hay un intercambio de información que no se ve. Una API es el intermediario que permite que dos programas se comuniquen: uno pide datos y el otro se los entrega con un formato acordado.

Pensalo como un restaurante: vos sos el cliente, la cocina es el servidor y el mozo es la API. Vos no entrás a la cocina; le hacés el pedido al mozo y él te trae el plato.

1. Los tres protagonistas

  • Cliente: la página web o la aplicación que usa la persona. Es la que hace el pedido.
  • Servidor (API): recibe el pedido, lo procesa y decide qué responder.
  • Base de datos: donde se guarda la información, como usuarios, productos o publicaciones.

2. El viaje de un pedido, paso a paso

  1. Hacés clic en "Ver publicaciones".
  2. El navegador envía un pedido a una dirección de la API, por ejemplo /api/publicaciones.
  3. La API busca las publicaciones en la base de datos.
  4. La base de datos devuelve los resultados.
  5. La API responde al navegador con los datos en formato JSON.
  6. La página muestra las publicaciones en pantalla.

Todo esto pasa en milisegundos, muchas veces por cada página que visitás.

3. Los métodos HTTP

Cada pedido indica qué querés hacer con un método. Estos son los cuatro más usados:

Método Acción Ejemplo
GET Leer información Ver la lista de publicaciones
POST Crear algo nuevo Publicar un comentario
PUT Modificar algo existente Editar tu perfil
DELETE Eliminar Borrar una publicación

4. JSON: el idioma de las APIs

La mayoría de las APIs responden en JSON, un formato de texto que se lee casi como una lista de datos: 

{
  "id": 4,
  "titulo": "Git y GitHub sin miedo",
  "categoria": "Herramientas",
  "fecha": "2026-10-14"
}

Consejo de RollingCode Blog

No necesitás saber back-end para empezar. Leer la documentación de una API pública es un gran ejercicio para entender cómo están organizados los datos.

5. Los códigos de respuesta

Junto con los datos, el servidor devuelve un número que indica cómo salió todo:

  • 200: todo salió bien.
  • 201: se creó algo nuevo.
  • 404: no se encontró lo que pediste. Es el mismo error de la página "Houston, tenemos un problema".
  • 500: hubo un error en el servidor.

Para seguir aprendiendo

Cuando llegues a la etapa de back-end vas a crear tus propias APIs. Mientras tanto, herramientas como Postman o Thunder Client te permiten enviar pedidos a APIs públicas y ver las respuestas sin escribir una sola línea de código.
